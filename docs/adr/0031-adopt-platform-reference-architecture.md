# 0031 — Adopt the platform reference architecture, with two amendments

- **Status:** Accepted
- **Date:** 2026-07-24
- **Deciders:** Platform team, Founder
- **Tags:** `architecture`, `platform`, `api`, `workflow`, `roadmap`

## Context

Pharmax has grown from a pharmacy operations console into the foundation
of a multi-tenant platform intended to serve compounding pharmacy
operations, telehealth orchestration, and external SaaS tenants
simultaneously. A reference architecture for that platform was drafted
(July 2026) covering method (domain-first decomposition, quantified
NFRs, ADRs, an incumbent capability matrix), a target shape (modular
monolith on an event backbone, RLS tenancy, versioned workflow engine,
public API as the wedge, four portals, adapter-isolated integrations,
compliance-as-generated-artifacts, AI sidecars), and ten closing
commitments.

A five-track conformance audit of the working tree found the
operational core already follows the document — RLS + session-GUC
tenancy (ADR-0004), the transactional outbox (ADR-0009), versioned
workflow policies pinned on every verification record (ADR-0008,
ADR-0017), the command-bus contract (ADR-0007), hash-chained audit with
WORM evidence (ADR-0006, ADR-0024) — while the platform half (public
versioned API, outbound partner webhooks, external portals,
compounding/DSCSA artifact generation, AI) does not exist yet. Two of
the document's rules also conflict with decisions this codebase has
already validated, and adopting them verbatim would be a regression.

## Decision

**Adopt the reference architecture as the north star for Pharmax, with
two amendments, and make the public v1 API plus outbound partner
webhooks the next platform milestone.**

The amended ten commitments are canonical as stated here:

1. Every row has a tenant (RLS + session-GUC; exemptions live in
   `prisma/migrations/rls-exempt.txt` and require security review).
2. Every state change is a versioned, registry-validated event.
3. Every side effect goes through the outbox.
4. Every workflow is versioned and pinned.
5. Every permission is explicit.
6. Every integration hides behind an adapter.
7. **(Amended)** Every capability a partner needs exists in the public
   API and is contract-tested; new external surfaces (provider,
   patient, developer portals) consume the public API. The internal
   ops console may keep privileged server functions inside the RLS
   tenant context — the invariant is API completeness, not dogfooding
   the transport.
8. Every AI output is a logged suggestion (model version + confidence
   in the audit trail; a human action commits it).
9. Every compliance artifact is generated by the workflow, not
   reconstructed after the fact.
10. Nothing goes distributed until a measurement forces it.

**Second amendment — tenant-authored rules stay subtractive.** The
overlay model (ADR-0017: overlays may forbid transitions and add
attestation requirements, never add transitions or weaken guards) is
retained as the _only_ tenant-facing rules surface for workflow safety
invariants. The planned rules-as-data expansion (per-org SLA
thresholds, bucket routing, notification rules) and its editor UI build
on the overlay vocabulary. A general JSON-logic guard engine authored
by tenant admins is explicitly rejected for safety-critical
transitions.

Scope and sequencing notes that bind future work:

- The workflow engine is applied where auditability has regulatory or
  contractual value (orders now; provider onboarding next). It is not
  a general ticketing engine.
- Portal order: provider portal with self-serve onboarding, then
  patient portal, then sales/commissions (an admin screen until
  displacement deals demand more).
- AI sidecars remain Phase 3 — nothing before the public API exists.
- Quantified throughput NFRs (orders/day, concurrent staff, queue-read
  p95) are to be added to `docs/ARCHITECTURE_PRINCIPLES.md`; recovery
  numbers already exist in the BC/DR policy.
- The incumbent capability matrix is built **exclusively** from public
  marketing pages, help centers, and demo videos, per
  `docs/governance/clean-room-development-policy.md`. Competitor
  implementation detail is never a design input.

## Consequences

**Easier:**

- Roadmap debates resolve against a written target instead of being
  re-litigated per feature; diligence reviewers get the platform
  thesis and its evidence trail in one place.
- The outbox backbone (ADR-0009) makes outbound partner webhooks a new
  consumer plus a subscription model — not a re-architecture.
- Amendment 7 avoids months rewriting the ops console against its own
  HTTP API for no user-visible gain.

**Harder / more expensive:**

- The public API becomes a permanent, versioned contract surface with
  its own compatibility, quota, and documentation obligations.
- Amendment 7 requires discipline without the forcing function:
  API completeness must be enforced by contract tests, since the ops
  console will not break when the public API lags.
- Keeping rules subtractive means some tenant customization requests
  will be declined or shipped slower than a generic rules engine
  would allow. That cost is accepted for workflow safety.

**Ongoing obligations:**

- New partner-relevant capability ⇒ public API endpoint + contract
  test in the same milestone, or an explicit ADR-referencing waiver.
- Any proposal to let tenants author guard logic beyond the overlay
  vocabulary requires a new ADR superseding the second amendment.
- Extraction of any module into a service must cite the measured
  constraint that forced it (commitment 10).

## Alternatives Considered

- **Adopt the reference document verbatim.** Rejected: commitment 7 as
  written regresses a validated server-component architecture, and an
  unconstrained rules engine undermines the workflow-safety invariants
  in ADR-0008/0017.
- **No formal adoption; keep deciding per feature.** Rejected: the
  audit showed divergence is concentrated in exactly the areas
  (platform surface) where ad-hoc decisions are most expensive to
  reverse.
- **Microservices-first platform build-out.** Rejected per ADR-0002
  and commitment 10; no measured constraint demands extraction.
