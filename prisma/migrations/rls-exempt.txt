# Migration RLS exemption list.
#
# Tables listed here are INTENTIONALLY not tenant-scoped at the RLS
# layer. The migration linter (`scripts/check-migration-rls.ts`)
# rejects any new `CREATE TABLE` that is neither paired with an
# `ENABLE ROW LEVEL SECURITY` policy in the same migration nor
# present here.
#
# Format: one bare lowercase table name per line. Lines starting
# with `#` are comments.
#
# Adding an entry here is a SOC 2 audit event. The reason MUST be
# documented inline as a comment ABOVE the table name and a code
# reviewer MUST sign off — exemptions weaken tenant isolation by
# construction and need an architecture-level justification.
#
# Current exemptions:

# System-wide registry of permission codes. Same rows visible to all
# organizations by design (every org reads from the same registry to
# look up permission ids). Modified only by migrations.
permission

# Junction table: Role <-> Permission. The Role rows ARE tenant-scoped
# (and RLS-protected), so cross-org leaks through this junction require
# first leaking a Role row, which the Role policy prevents. Keeping
# this junction out of RLS avoids an extra subquery on every join.
role_permission

# Junction table: Clinic <-> Site. Same logic as role_permission —
# both Clinic and PharmacySite ARE tenant-scoped, so the parent
# policies close the leak surface.
clinic_site

# Inbound Stripe webhook events. Arrive BEFORE the platform knows
# which tenant the event resolves to; the dispatcher resolves the
# tenant from the Stripe customer id and enters a tenancy context
# for the actual side-effect. The raw event store is platform-level.
stripe_webhook_event

# Inbound EasyPost (carrier tracking) webhook events. Same reason as
# stripe_webhook_event: the platform doesn't know which tenant a
# tracker event belongs to until the worker drain resolves the
# shipment by tracking number (in system context) and enters that
# org's tenancy to execute RecordShipmentTrackingEvent.
easypost_webhook_event

# Inbound FedEx Advanced Integrated Visibility webhook events. Same
# reason as easypost_webhook_event: the platform doesn't know which
# tenant a tracking event belongs to until the worker drain resolves
# the shipment by tracking number (in system context) and enters that
# org's tenancy to execute RecordShipmentTrackingEvent. The stored
# payload is a PHI-minimized projection (see
# projectFedExWebhookForStorage).
fedex_webhook_event

# Inbound Clerk (identity) webhook events. Arrive BEFORE the platform
# resolves them to a Pharmax user row (and thus an organization). The
# dispatcher in apps/web/src/server/auth/clerk-webhook-handlers.ts
# resolves the tenancy from `user.clerkUserId` inside a system-context
# frame. The raw delivery ledger (svix-id idempotency key) is
# platform-level by construction.
clerk_webhook_event

# Inbound Resend (email delivery) webhook events. Same reason as
# clerk/stripe/easypost: Svix-signed events arrive BEFORE the platform
# knows which tenant (if any) they resolve to. The dispatcher joins the
# event to a notification_delivery row by Resend `email_id` and updates
# the (RLS-protected, org-scoped) projection in system context. The raw
# event store (svixMessageId idempotency key) is platform-level.
resend_webhook_event

# Sign-in attempt ledger for the in-house identity engine (ADR-0030).
# Pre-tenant by construction: a failed attempt against a nonexistent
# email has no resolvable organization, so `organizationId` is nullable
# and cannot back an RLS predicate. The engine uses this table for
# distributed lockout and brute-force detection; reads are scoped by
# `emailAttempted` / `ipAddress` in system context. Contains no PHI
# (email is an operator identifier). All OTHER auth tables
# (auth_session, mfa_enrollment, recovery_code, password_history,
# password_reset_token) ARE org-scoped and RLS-protected.
login_attempt

# Break-glass session envelope (@pharmax/security). Sessions open a
# cross-tenant `pharmax_system` context for forensic / repair work, so
# there is no organizationId to back an RLS predicate. Access is
# narrowed one layer up: only @pharmax/security's system-context code
# paths touch the model, the Prisma tenancy extension excludes it from
# auto-scoping, and the grant layer withholds DELETE (append-only
# evidence). See packages/security/src/break-glass/SCHEMA.md.
break_glass_session

# Per-operation ledger for break_glass_session (same cross-tenant
# rationale). INSERT-only at the grant layer — rows are immutable
# audit evidence of exactly what was executed under the bypass.
break_glass_action
